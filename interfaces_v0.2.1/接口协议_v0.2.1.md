# 紧急救援赛四足机械狗｜三模块统一接口协议 v0.2.1

> **状态：可作为三人立即开工的首版公共开发契约；硬件参数尚未冻结。**  
> **适用：** 视觉 A、运动与主控 B、机械臂 C 的并行开发，Python 3.10+。  
> **配套代码：** `rescue_contracts/types.py`、`rescue_contracts/interfaces.py`、`mocks/fake_devices.py`、`tests/test_contracts.py`。  
> **原则：** 优先把数据类型和跨模块规则统一。未拿到实物前，只验证软件行为，不假定 SDK 支持某个动作或能确认硬件成功。

## 0. 文档依据、已知事实与项目约定

**赛事指导书已经明确的内容：** 自主阶段要求黑线循迹、黄/黑立牌识别；约 20 cm 处蜂鸣报警，黄牌绕行、黑牌用机械臂击倒；赋值区识别颜色球并投入 2 倍或 3 倍任务杯；随后返回出发区切换 FPV 遥控阶段。自主阶段不得由人遥控，赛场全程比赛设备断网。比赛主控为树莓派 CM5 或赛事允许的同等级平台，具体实物以现场与设备为准。参见《紧急救援赛实验指导书(6).pdf》第 3–9、14–22、23–42、43–49、55–58、71–79 页。

**已有 XGO 教程中的硬件 API：** `dog.move('x', step)`、`dog.turn(step)`、`dog.stop()`、`dog.arm(x,z)`、`dog.claw(pos)` 等接口已经在《2.四足机械狗如何开发学习.docx》第 11–23 页给出。教程中的平移参数是步幅/步长控制量，不能当作实际累计位移；`turn` 教程标注 °/s；`arm` 教程使用相对机械臂基座的 X/Z（mm）而非图像像素；`claw` 为 0–255 控制值。这份教程不证明最终参赛实物采用同样固件或支持同样组合控制。

**本文件新增的是项目自行约定的接口，非赛事官方规定，也不是厂家 SDK 原生函数。** 所有默认周期、阈值与 Mock 行为都必须在实物到手后重新测量。赛事指导书中的 `FWD:0.5` 等为示例字符串指令，不能直接视作确认的厂家速度接口。

## 1. 模块边界与调用关系

```text
                  主程序 RescueController / FSM
                 /                |                 \
      CameraSource → Vision       Motion             Arm
                       |             |                 |
                    识别结果      运动 SDK 适配       机械臂 SDK 适配
                         \         /                  /
                 控制权管理 / 安全监控 / 请求互锁
                 （辅助：蜂鸣器、日志、遥控输入）
```

- **A 视觉**：接受一帧 BGR 图像及关注目标集合；仅返回检测数据。**禁止**直接调用 Motion/Arm/蜂鸣器。
- **B 运动与主控**：实现 Motion，使用 `VisionResult` 构建任务 FSM 和循迹；统一持有控制模式、通信互锁、报警调用及后续 SDK 接入协调。**禁止**在主控中复制视觉检测算法或机械臂动作底层实现。
- **C 机械臂**：接收高层任务动作，内部执行预设姿态/夹爪步骤，维护动作生命周期及超时。**禁止**自行用摄像头像素直接计算未标定的机械坐标、或自行驱动底盘绕行。
- **真实 SDK 适配层**：只将上述协议翻译到确实支持的厂家函数；不可达或不支持时明确返回错误。Motion 和 Arm 如果共用一条底层通信链路，必须复用同一连接管理器，禁止独立抢占串口。

## 2. 公共数据约定

### 2.1 单位与坐标系

| 数据 | 单位 | 正方向/约定 |
|---|---|---|
| 图像坐标 `(u,v)` | px | 图像左上角为原点，u 向右、v 向下 |
| 图像面积 | px² | 从检测轮廓/掩膜得到的二维面积 |
| 黑线误差 `error_px` | px | `检测黑线中心 u - 参考中心 u`；负数在左，正数在右 |
| 机身坐标 `(X,Y,Z)` | mm | X 前、Y 左、Z 上；以明确的机身参考点为原点 |
| 机械臂坐标 `(X,Y,Z)` | mm | **机械臂基座坐标系**，不同于机身/相机坐标 |
| 角度、角速度 | deg、deg/s | 俯视逆时针/左转为正 |
| 时间 | ms | 同一控制进程内 `time.monotonic_ns() // 1_000_000` |
| 实时运动控制 `x_norm/y_norm/yaw_norm` | 无量纲 | 归一化 `[-1,1]`，不等于 mm/s |
| 颜色与目标类别 | 枚举 | 不允许自由拼写随意变体 |

如果相机朝向、机械臂安装位置或图像镜像发生变化，**必须保证公开接口对外仍遵守本坐标约定**，不能让上层任务代码自行处理不同摄像头的轴翻转。

像素位置不能直接传成毫米坐标。`Detection.position_body_mm` 和 `Detection.distance_mm` 只有在完成相机内参、外参或测距标定后才允许赋值；未完成时必须使用 `None`。若使用 `distance_mm` 做“约 200 mm 报警”，需在标定记录中写明测距参考点（建议机器人前缘）及裁判口径仍需确认，不得以普通二维物体面积直接假称真实距离。

### 2.2 时间戳与幂等

- `timestamp_ms` 表示产生图像/命令时的**单调时钟**时间；不是 Unix 时间戳。Mock 使用注入式 `FakeClock`。
- 每个**离散动作请求**必须拥有新的非空 `request_id`；同一 `request_id` 重发且内容完全一致，应返回既有结果，不得重复击倒、抓球或投放；编号相同但请求不同，返回 `CONFLICT`。
- **连续运动控制的每一次更新必须产生新的 `request_id`**。重复同一请求不得延长原有 TTL。
- `CommandAck.accepted=True` 只代表接口接受请求，**不代表机械狗已经运动、停稳，或已完成抓取**。
- 所有不支持的运动组合、机械坐标、反馈类型一律使用 `UNSUPPORTED`/`UNREACHABLE` 明确拒绝，**不允许默默丢掉控制分量或伪造执行成功**。

### 2.3 公共错误码（`ErrorCode`）

`INVALID_ARGUMENT`、`STALE_DATA`、`BUSY`、`UNSUPPORTED`、`TIMEOUT`、`COMM_ERROR`、`UNREACHABLE`、`SAFETY_STOP`、`MODE_DENIED`、`CONFLICT`、`NOT_READY`、`NOT_FOUND`、`INTERNAL_ERROR`。

**区别：**“画面正常但没有找到目标”是有效的视觉结果，不是 `COMM_ERROR` 或程序异常。

常规输入异常用协议状态/拒绝结果表达，不让模块调用直接崩溃；意料外内部异常在模块边界记录后转成 `INTERNAL_ERROR`，再由主控采取措施。不要统一吞掉错误并返回 `True`。

## 3. A：视觉接口 Vision API

### 3.1 唯一必需入口

```python
def observe(frame: ImageFrame, interests: set[TargetType]) -> VisionResult: ...
```

**输入 `ImageFrame`：**

| 字段 | 类型 | 含义 |
|---|---|---|
| `bgr` | `np.ndarray` | OpenCV BGR，H×W×3；算法负责人实际校验 `dtype` 与像素通道 |
| `frame_id` | `int` | 单调增加的帧编号 |
| `timestamp_ms` | `int` | 采集帧时刻，单调时钟 ms |
| `width`、`height` | `int` | 图像尺寸 px，必须和数组形状一致 |
| `interests` | `set[TargetType]` | 可选 `LINE`、`SIGN`、`BALL`、`CUP`、`BLOCK`、`STORAGE_AREA` 关注类别 |

**输出 `VisionResult`：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `frame_id`、`timestamp_ms` | `int` | 保留原始帧编号/采集时间，不改成识别完成时间 |
| `status` | `VisionStatus` | `OK`、`INVALID_FRAME`、`STALE_FRAME`、`AMBIGUOUS`、`PROCESSING_ERROR` |
| `line` | `LineDetection | None` | 没有请求 `LINE` 时为 `None`；请求了但丢线时 `found=False` |
| `objects` | `list[Detection]` | 没检测到目标时为空列表，仍可 `status=OK` |
| `error_code`、`message` | 错误码/文本 | 需要时记录原因 |

**`LineDetection`：** `found: bool`；`error_px: float|None`（若未发现必须为 `None`）；`quality: float`（0～1 的算法质量指标，**不是校准后识别正确概率**）。

**`Detection`：**

| 字段 | 类型 / 单位 | 说明 |
|---|---|---|
| `kind` | `TargetType` | 目标大类 |
| `center_px` | `(float,float)` px | 中心 (u,v) |
| `bbox_xywh_px` | `(int,int,int,int)` px | 左上 (u,v)、宽、高 |
| `area_px2` | `float` px² | 像素面积 |
| `score` | `float` 0～1 | 算法定义的检测质量/分数 |
| `confirmed` | `bool` | 是否通过事先定义的时序一致性判定 |
| `color` | `TargetColor|None` | 红/绿/蓝/黄/黑；不适用时为 `None` |
| `cup_multiplier` | `int|None` | 只在杯识别确定时填 2 或 3 |
| `position_body_mm` | 三维坐标或 `None` | 有相机/目标标定后才使用 |
| `distance_mm` | `float|None` | 已定义测距参考点并标定后才使用 |

**识别时序建议：** 初期对黄/黑牌类别采用“最近 5 次检测至少 3 次一致”确认；循迹误差应尽量逐帧更新，而不是强制等待 5 帧。建议初期最大图像年龄 `200 ms`（配置项），实时性能后续测试决定。第一优先级是黑线、黄/黑立牌、三色球；杯和颜色块属于可扩展目标，不能拖延第一批交付。

**A 模块异常：** `bgr` 为空/格式错误 → `INVALID_FRAME`；已过期 → `STALE_FRAME`；黑线未检测到 → `status=OK` 且 `line.found=False`；立牌歧义 → `AMBIGUOUS`；摄像头断连 → `CameraSource` 报错，主控负责停止移动。A 不自行调用 SDK 或 `motion.stop()`。

## 4. B：运动接口 Motion API

### 4.1 基础控制（首批必须实现）

```python
def drive(command: DriveCommand) -> CommandAck: ...
def stop(request_id: str) -> CommandAck: ...
def get_motion_status() -> MotionStatus: ...
```

**`DriveCommand`：**

| 字段 | 类型 | 初期规则 |
|---|---|---|
| `request_id` | `str` | 非空，每次实时控制更新使用新 ID |
| `timestamp_ms` | `int` | 发送时单调时钟 ms；到达时已过有效期拒绝 |
| `x_norm` | `float` | `[-1,1]`，正前进，负后退 |
| `y_norm` | `float` | `[-1,1]`，正左移，负右移 |
| `yaw_norm` | `float` | `[-1,1]`，正左转，负右转 |
| `ttl_ms` | `int` | 初期接口允许 `100..2000 ms`，建议调试默认 `400 ms` |
| `source` | `CommandSource` | `AUTO` 或 `REMOTE`；`SAFETY` 只允许发停止类操作 |

**参数校验：** 拒绝 NaN、无穷大、布尔值、范围外数值、非法 TTL、重复编号却改变参数。若 SDK 不支持同时前进加转向/横移，则返回 `UNSUPPORTED`，不要悄悄丢弃 `yaw_norm`。

**`CommandAck`：** `request_id`、`accepted`、`timestamp_ms`、`error_code`、`message`。**只有接受含义，没有“实际速度已达到/已停稳”含义。**

**`MotionStatus`：** `timestamp_ms`、当前 `commanded: DriveCommand|None`、`measured_state`（`UNKNOWN / STOPPED / MOVING`）、`last_command_ms`、`watchdog_expired`、`error_code`。无可靠里程计/IMU/硬件反馈时，`measured_state=UNKNOWN`，不能靠上一条指令推断物理状态。

**运动控制周期（可调整的初始建议）：** 主控每 `50..100 ms` 发送新请求；控制看门狗每 `≤50 ms` 独立检查；超过 TTL 立即尝试 `stop`、进入 `SAFE`，并且在故障被确认处理前不能继续自主/遥控运动。**程序崩溃时的软件看门狗未必还会运行，必须另外验证下位机失联自动停车能力。** Mock 通过独立的 `MotionWatchdog.check()`（底层仍可用 `tick()` 驱动注入时钟）模拟看门狗，不等于实物具备安全停车。

### 4.2 可选的高级运动动作（本版只预留，不是首批必需能力）

```python
# v0.3 可选扩展，不在当前 MotionAPI 强制接口中
def move_distance(distance_mm: float, timeout_ms: int): ...
def rotate_angle(angle_deg: float, timeout_ms: int): ...
```

只有获得可信位移/角度反馈并定义完成标准后，才可宣称闭环精确控制。依靠步态时长估计的开环操作，要标注为“近似位移/近似转角”，不可返回未经验证的精确成功。

### 4.3 异常和运动互锁

- 运动时请求机械臂操作 → `BUSY`（主控制器可先 `stop` 再等待机身稳定）。
- 机械臂操作未结束时请求行走 → `BUSY`。
- `stop()` 在 `SAFE/AUTO/REMOTE` 均可调用且高优先级，但 **`stop()` 仅请求底盘停止，不等于电机卸力、全机急停或已物理停稳**。
- 底层通信失败 → `COMM_ERROR` 并触发安全控制；物理停车结果未知则报告未知，不能返回伪成功。

## 5. C：机械臂接口 Arm API

### 5.1 必需的三个函数

```python
def start_action(request: ArmActionRequest) -> ActionAck: ...
def get_status(action_id: str) -> ActionResult: ...
def cancel_action(action_id: str, request_id: str) -> CommandAck: ...
```

> 与 v0.2 对比，`cancel_action` 明确增加 `request_id`，用于取消请求幂等校验；这是 v0.2.1 的**兼容性调整**，各组须统一使用新签名。

**`ArmActionRequest`：**

| 字段 | 类型 / 单位 | 说明 |
|---|---|---|
| `request_id` | `str` | 每次启动动作唯一编号 |
| `timestamp_ms` | `int` ms | 创建时间 |
| `action` | `ArmAction` | 必须在下表动作枚举内 |
| `target` | `ArmTarget|None` | 目标信息；预设动作可使用 `None` |
| `timeout_ms` | `int` ms | 首版允许 `100..30000 ms`，逐动作调参 |
| `source` | `CommandSource` | 必须匹配当前控制模式 |

`ArmAction` 可选：`HOME`、`HIT_SIGN`、`PICK_BALL`、`PLACE_CUP_2X`、`PLACE_CUP_3X`、`PICK_BLOCK`、`PLACE_STORAGE`、`OPEN_CLAW`、`CLOSE_CLAW`。

**`ArmTarget`：** `color: TargetColor|None`、`preset_id: str|None`、`position_arm_mm: tuple[float,float,float]|None`、`source_frame_id: int|None`。`position_arm_mm` 是三维机械臂基座坐标，用于未来三维定位能力；若厂家接口只有 X/Z，则不得忽略非零 Y。初期抓球优先使用预设动作 + 机身对准，不能把 `center_px` 直接当机械臂毫米坐标。使用未标定预设动作应返回 `NOT_READY`。

**`ActionAck`：** `request_id`、`accepted`、`timestamp_ms`、`action_id|None`、`error_code`、`message`。请求被接受后，必须返回可用于轮询的 `action_id`。

**`ActionResult`：** `action_id`、`state`、`timestamp_ms`、`started_ms`、`finished_ms`、`error_code`、`message`。未知 `action_id` 返回 `FAILED + NOT_FOUND`，不能误当任务本身失败。

### 5.2 动作生命周期

`ACCEPTED → RUNNING → DONE_UNVERIFIED`：动作序列结束，但物理结果尚未得到验证。  
`ACCEPTED/RUNNING → FAILED/TIMEOUT/CANCELLED`：失败、超时或安全确认后的取消。  
`SUCCESS` **只有存在可信的目标完成验证**时才能返回；否则必须保持 `DONE_UNVERIFIED`，由主控结合视觉或其他传感器决定“球是否真正抓到”。

**取消语义：** `cancel_action()` 返回 `accepted=True` 仅说明取消请求被受理；真实硬件必须确认已终止后，动作才能进入 `CANCELLED`。如果 SDK 无法取消则返回 `UNSUPPORTED`，不得把未停的机械臂标记为 `CANCELLED`。

**超时锁定：** 超时或通信异常之后，如果机械臂是否仍在运动不确定，应保留机械臂/底盘互锁，进入安全恢复流程；不能因为 Python 超时了，就允许机械狗突然前进。随包 Mock 对超时保留互锁，测试用 `release_after_safety_check()` 仅模拟外部确认，**绝不可在实物代码中未经确认直接清锁**。

**动作实现建议：** `PICK_BALL` 可分成夹爪张开、机身停稳、机械臂下探、闭合、抬起、回安全姿态等步骤，具体位置、速度、停留时长暂留配置文件，不写死为厂家教程示例角度。黑牌击倒、2 倍杯与 3 倍杯投放分别标定预设动作。

## 6. 控制权、任务时序与辅助接口

### 6.1 控制模式

- `SAFE`：默认上电模式，停止请求可以通行；不允许普通 `AUTO/REMOTE` 运动或机械臂动作。
- `AUTO`：只接受自主状态机来源；遥控输入不得绕过控制权管理器。
- `REMOTE`：只接受遥控来源；自主状态机不得继续发送运动命令。
- 真正进入 `REMOTE` 前，必须依据比赛规则确认已完成自主阶段、机器人已完全回到出发区并允许接触/切换。软件应检查可自动检测的条件，其余由现场操作流程确认。
- 模式切换、资源互锁和硬件通讯独占由 B 的主控制器统一协调；Mock `ControlGate` 仅模拟权限检查，不包含裁判确认等现场条件。

### 6.2 典型黑牌任务调用顺序

```text
CameraSource 取最新帧 → Vision.observe({LINE,SIGN})
→ 多帧确认黑牌 & 经标定的接近条件成立
→ Motion.stop() → 等待机身稳定/检查可用反馈
→ Buzzer.beep(duration_ms) → Arm.start_action(HIT_SIGN)
→ Arm.get_status(action_id) 周期查询
→ 如 DONE_UNVERIFIED：主控尝试视觉确认牌子已倒
→ 若成功：继续循迹；若未确认：按预设时间预算有限重试/放弃
```

这里蜂鸣器属于**辅助服务**，建议调用形式 `beep(request_id: str, duration_ms: int) -> CommandAck`；它不占用三个主要模块接口名。初期蜂鸣 300–500 ms 可作为调试参考，须以现场听觉效果调整。

### 6.3 主控调度建议（初始值非硬件保证）

| 服务 | 责任人 | 初期建议 |
|---|---|---|
| CameraSource | A | 后台采帧，保存最新一帧，避免旧帧排队 |
| Vision | A | 按性能 10–20 Hz 或以最新帧可用为准 |
| FSM/循迹控制 | B | 50–100 ms 一次，处理最新的有效 VisionResult |
| 运动过期看门狗 | B | 与耗时视觉、机械臂动作解耦，≤50 ms 一次 |
| Arm 状态查询 | C/B | 约每 50–100 ms 查询，不能在主循环里 `sleep(数秒)` |
| 日志记录 | B | 至少含单调时间、request_id、状态与 error_code |

视觉帧超过最大年龄不得继续驱动循迹；丢线按 FSM 设计执行有限搜索或停车。机械臂的 `RUNNING` 状态不得阻塞安全监测。比赛 10 分钟总计时归主控管理。

## 7. Mock 与接口验收（不接硬件也可测试）

**运行环境：** Python 3.10+；当前合约代码、Mock、`unittest` 只用 Python 标准库。真正视觉实现需安装 NumPy/OpenCV。进入项目目录执行：


包内的 **基础合约测试已在生成环境中通过**，当前另有 B 组 FSM/模式看门狗扩展测试；覆盖：视觉无目标、黑线偏差符号、目标过滤、旧帧/无效帧；运动归一化校验、控制权隔离、命令过期、组合运动能力判断、TTL 看门狗、重复 ID 不延长 TTL；机械臂/底盘互锁、动作状态流转、超时锁定、取消支持与不支持、动作幂等、未知编号等。测试数量随实现扩展，以 `python -m unittest discover -s tests -v` 的当前结果为准。

**重要：这些测试证明的是协议和 Mock 行为，不证明真实机器人运动、抓取或安全急停有效。** 各人开发的实现应在不修改 `rescue_contracts/` 公共数据定义的前提下复用/扩展契约测试。

## 8. 三名队员的开工任务与交付物

### A｜视觉识别（现在就能做）

1. 实现 `VisionAPI.observe()`，对接离线图片/视频；摄像头采集采用独立 `CameraSource`。

3. 提供 HSV / ROI 阈值配置，不把某个比赛现场阈值写死到契约类型中；做多帧确认但不能强迫循迹也等待确认。

3. 实现 `ControlMode`、`CommandSource` 权限、独占控制、底盘/机械臂互锁、独立运动 TTL 检查。
4. 实现最小 `Buzzer` 辅助封装，并在模拟状态机中接上报警动作。
5. **首批提交：** `motion/`、`controller/`、Mock 仿真日志、FSM 正常/异常路径测试及接口兼容结果。

### C｜机械臂与夹爪（现在就能做）

1. 实现 `ArmAPI` 的异步任务执行框架、内部步骤执行器、动作编号与状态跟踪。
2. 优先准备 `HOME/HIT_SIGN/PICK_BALL/PLACE_CUP_2X/PLACE_CUP_3X` 的**预设动作参数框架**（不虚构具体舵机角度/姿态）。
3. 实现机械臂占用锁、超时后的安全锁定、取消能力报告、同 ID 只执行一次。

## 9. 抢先联调顺序与交接点

1. 先共同运行配套协议/Mock 测试，确认环境一致；不要把测试数量写死在成员分支说明中。
2. A 的 Vision 接入 B 的模拟 FSM，只传 `VisionResult`，不交叉调用硬件。
3. C 的 Arm 接入 B 的 FSM，至少完成 `PICK_BALL → DONE_UNVERIFIED → 主控验证` 模拟流程。
4. 运行黄牌绕行、黑牌报警击倒、两球投杯、返回出发区的模拟任务；通过后才开始 SDK 适配。
5. 拿到狗后按安全顺序：硬件型号与 SDK 识别 → 单独测试停止/基础移动 → 机械臂极限位安全标定 → 摄像头内外参/工作视野 → 单任务 → 完整任务 → 10 分钟演练。

## 10. 拿到实物之后必须确认，不能先验假定

- 机器人具体型号、CM4/CM5 平台、操作系统、真实固件与 `xgolib` 版本；是否符合赛事允许的平台要求。
- X/Y/Yaw 的真实量程、组合运动支持情况、实际速度、转向响应、掉帧/延迟对控制的影响。
- 下位机是否支持上位机失联自动停车；`stop()` 是否仅停腿部，何时可认为机械狗静止。
- 机械臂真实自由度、SDK 的三维坐标能力、可达空间、夹爪控制值、硬件限位与电流/堵转保护。
- 摄像头安装位置、图像是否镜像、自动阶段相机和 FPV 相机是否可共用；立牌约 200 mm 报警的物理参考点如何校准。
- 机械臂动作是否可中断，是否能确认抓取成功；若不可，则回到主控视觉验证与人工可执行策略。

## 11. 版本冻结范围（向三人发放后的规则）
