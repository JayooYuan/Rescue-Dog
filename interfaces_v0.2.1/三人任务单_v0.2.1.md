# 给三位队员的开工任务单（配套 v0.2.1）

## 所有人先完成的共同事项

1. 阅读 `接口协议_v0.2.1.md`，尤其是坐标、单位、错误码及 `DONE_UNVERIFIED`。
2. 安装 Python 3.10+，运行 `python -m unittest discover -s tests -v`，确认当前协议与 Mock 测试全部通过（数量以命令输出为准）。
3. **不得各自改动** `rescue_contracts/types.py` 与 `rescue_contracts/interfaces.py`，若有改动需求提交提案。
4. 先实现不依赖真实机械狗的功能；SDK、参数标定在拿到机器后处理。

## A：视觉（首批任务）

- 对照 `VisionAPI.observe(frame, interests)` 输出 `VisionResult`。
- 使用照片/视频实现黑线误差、黄/黑立牌和红绿蓝球识别。
- 记录实际检测质量分数的定义、识别 ROI 与 HSV 可配置参数。
- 异常覆盖：空帧、过期帧、无目标、黑线与黑牌混淆、颜色识别冲突。
- 交付：视觉模块源码、离线测试素材/结果、运行方法和已知限制。距离 mm 没标定时一律 `None`。

## B：运动与主控（首批任务）

- 对照 `MotionAPI` 实现运动命令校验、标准返回结构、模式与互锁。
- 建立自主 FSM 的 Mock 可运行主流程：循迹 → 牌识别 → 报警 → 绕行/击倒 → 找球 → 投杯 → 返航。
- 设置独立的运动有效期检查，控制权 `SAFE/AUTO/REMOTE` 不可乱切。
- 协助 A/C 在统一主程序中完成联调；蜂鸣器以独立辅助服务调用。
- 交付：运动模块、FSM、Mock 联调记录、故障与超时测试。

## C：机械臂（首批任务）

- 对照 `ArmAPI` 建立异步动作生命周期；保持 `action_id` 与请求幂等。
- 为 `HOME/HIT_SIGN/PICK_BALL/PLACE_CUP_2X/PLACE_CUP_3X` 创建可配置的步骤模板，暂不写死未经实测的舵机角度。
- 维护与底盘的互锁和超时安全锁，明确取消/未知动作等异常。
- 交付：动作模块、Mock 状态记录、单元测试、待核实硬件能力列表。

## 第一轮集成验收

- A 给 B 提供符合契约的 `VisionResult`；B 不需要读取 A 内部 HSV 中间数据。
- C 给 B 提供符合契约的 `ActionAck/ActionResult`；B 不直接控制 C 的舵机角度。
- B 以 Mock 输入走通“黑牌识别→停止→报警→击倒→继续循迹”和“抓球→投杯”两条流程。
- 接口改动先统一升级，不允许三个子模块出现不同版本的 `ActionState`、`TargetType`、`ErrorCode`。
